# supplier-management Specification

## Purpose
Behavior of the supplier-management capability, accumulated from StoryLoop changes.

## Requirements

### Requirement: 『业务管理』目录与供应商管理菜单

_Story S1, from FEAT-20260918-001_

As 系统管理员, 在系统菜单中看到一个新的『业务管理』目录，其下有『供应商管理』菜单和对应的按钮权限, so that 我可以通过角色把供应商管理的访问权和各项操作权分配给不同用户.

The system SHALL 『业务管理』是一个新的顶级目录
The system SHALL 『供应商管理』菜单挂在『业务管理』目录下
The system SHALL 供应商管理有五个独立的按钮级权限：列表（查询）、新增、修改、删除、导出
The system SHALL 没有供应商管理菜单权限的用户在导航中看不到该菜单（本期不验收）

#### Scenario: A1 列表中有顶级目录『业务管理』，其下有菜单『供应商管理』，该菜单下有查询、新增、修改、删除、导出五个按钮权限
- **GIVEN** 系统已完成初始化，管理员 admin 已登录
- **WHEN** 管理员查看菜单管理列表
- **THEN** 列表中有顶级目录『业务管理』，其下有菜单『供应商管理』，该菜单下有查询、新增、修改、删除、导出五个按钮权限

#### Scenario: A2 导航中出现『供应商管理』，点击后打开供应商列表页面
- **GIVEN** 管理员 admin 已登录前端
- **WHEN** 管理员展开左侧导航的『业务管理』
- **THEN** 导航中出现『供应商管理』，点击后打开供应商列表页面

### Requirement: 分页查询供应商

_Story S2, from FEAT-20260918-001_

As 有供应商列表权限的业务人员, 按供应商名称和状态分页查询供应商列表, so that 我能快速找到要查看或维护的供应商.

The system SHALL 列表显示供应商编码、名称、联系人、联系电话、状态、备注
The system SHALL 查询条件只有名称和状态，条件可以组合，也可以都不填
The system SHALL 名称条件为模糊匹配：供应商名称包含输入内容即命中
The system SHALL 状态沿用系统字典 sys_normal_disable，只有 0=正常（启用）和 1=停用 两种
The system SHALL 查询结果分页显示，并展示总条数
The system SHALL 已删除的供应商不出现在列表中
The system SHALL 没有列表权限的用户调用查询接口时被拒绝

#### Scenario: A4 返回成功，结果含当前页记录和总条数，每条记录包含编码、名称、联系人、联系电话、状态、备注
- **GIVEN** 系统中有多条供应商记录，用户拥有供应商列表权限
- **WHEN** 用户不带任何条件请求第 1 页供应商列表
- **THEN** 返回成功，结果含当前页记录和总条数，每条记录包含编码、名称、联系人、联系电话、状态、备注

#### Scenario: A5 结果只包含停用的供应商
- **GIVEN** 系统中有一条启用（状态 0）的供应商和一条停用（状态 1）的供应商
- **WHEN** 用户以状态为停用作为条件查询
- **THEN** 结果只包含停用的供应商

#### Scenario: A6 结果包含该供应商，且不包含名称不匹配的供应商
- **GIVEN** 系统中有一条名称已知的供应商
- **WHEN** 用户以该供应商的完整名称作为名称条件查询
- **THEN** 结果包含该供应商，且不包含名称不匹配的供应商

#### Scenario: A25 结果包含名称已知的供应商，且不包含名称里没有这段文字的供应商
- **GIVEN** 系统中有一条名称已知的供应商，以及一条名称不包含某段文字的供应商
- **WHEN** 用户只用该已知名称中间的一段文字（不是完整名称）作为名称条件查询
- **THEN** 结果包含名称已知的供应商，且不包含名称里没有这段文字的供应商

#### Scenario: A7 请求被拒绝，并提示未登录
- **GIVEN** 用户未登录
- **WHEN** 用户请求供应商列表
- **THEN** 请求被拒绝，并提示未登录

#### Scenario: A8 表格只显示符合条件的供应商，并显示分页控件
- **GIVEN** 管理员已登录前端
- **WHEN** 管理员打开供应商管理页面，输入名称条件后点击搜索
- **THEN** 表格只显示符合条件的供应商，并显示分页控件

### Requirement: 新增供应商

_Story S3, from FEAT-20260918-001_

As 有供应商新增权限的业务人员, 录入一个新的供应商档案, so that 系统里有这个供应商的基础信息，后续业务可以使用.

The system SHALL 新增时录入供应商编码、名称、联系人、联系电话、状态、备注
The system SHALL 供应商编码由用户手工录入，必填，在未删除的供应商中唯一；已删除供应商的编码可以被新供应商再次使用
The system SHALL 供应商名称必填，不要求唯一
The system SHALL 联系人和联系电话都是选填，联系电话不校验格式
The system SHALL 新增时状态默认为启用（0=正常）
The system SHALL 没有新增权限的用户在页面上看不到新增按钮（本期不验收），调用新增接口时被拒绝

#### Scenario: A9 返回成功，之后按该名称查询能查到这条新供应商，各字段与提交的一致
- **GIVEN** 用户拥有供应商新增权限，系统中还没有编码为 X 的供应商
- **WHEN** 用户提交一个编码为 X 且信息完整有效的供应商
- **THEN** 返回成功，之后按该名称查询能查到这条新供应商，各字段与提交的一致

#### Scenario: A10 新增失败，并提示编码重复，系统中编码为 X 的供应商仍只有一条
- **GIVEN** 系统中已有编码为 X 的供应商
- **WHEN** 用户再提交一个编码同为 X 的供应商
- **THEN** 新增失败，并提示编码重复，系统中编码为 X 的供应商仍只有一条

#### Scenario: A11 新增失败，并提示名称必填
- **GIVEN** 用户拥有供应商新增权限
- **WHEN** 用户提交一个没有名称的供应商
- **THEN** 新增失败，并提示名称必填

#### Scenario: A26 新增失败，并提示编码必填，系统中没有新增这条供应商
- **GIVEN** 用户拥有供应商新增权限
- **WHEN** 用户提交一个有名称但没有编码的供应商
- **THEN** 新增失败，并提示编码必填，系统中没有新增这条供应商

#### Scenario: A27 返回成功，按名称 N 查询能查到两条供应商
- **GIVEN** 系统中已有一条名称为 N 的供应商
- **WHEN** 用户提交一个名称同为 N、编码不同的供应商
- **THEN** 返回成功，按名称 N 查询能查到两条供应商

#### Scenario: A28 返回成功，再查询该供应商时联系人和联系电话为空，状态为启用（0）
- **GIVEN** 用户拥有供应商新增权限
- **WHEN** 用户提交一个只填了编码和名称、不填联系人、联系电话和状态的供应商
- **THEN** 返回成功，再查询该供应商时联系人和联系电话为空，状态为启用（0）

#### Scenario: A29 返回成功，再查询该供应商时联系电话与提交的一致
- **GIVEN** 用户拥有供应商新增权限
- **WHEN** 用户提交一个联系电话为任意非号码格式文字的供应商
- **THEN** 返回成功，再查询该供应商时联系电话与提交的一致

#### Scenario: A12 弹窗关闭，页面提示操作成功，列表中出现新增的供应商
- **GIVEN** 管理员已登录前端，打开了供应商管理页面
- **WHEN** 管理员点击新增，填写表单并确认
- **THEN** 弹窗关闭，页面提示操作成功，列表中出现新增的供应商

### Requirement: 修改供应商

_Story S4, from FEAT-20260918-001_

As 有供应商修改权限的业务人员, 修改已有供应商的档案信息，包括启用或停用, so that 供应商信息变化或合作状态变化时，系统数据能保持准确.

The system SHALL 可以修改名称、联系人、联系电话、状态、备注
The system SHALL 供应商编码创建后不可修改
The system SHALL 修改后仍要满足新增时的校验规则（名称必填、联系人和联系电话选填且不校验格式）
The system SHALL 状态只能在修改表单中变更，列表中不提供启用/停用快捷开关
The system SHALL 已删除的供应商不能再查看详情
The system SHALL 没有修改权限的用户在页面上看不到修改按钮（本期不验收），调用修改接口时被拒绝

#### Scenario: A13 返回成功，再查询该供应商时联系人为新值，状态为停用（1）
- **GIVEN** 系统中有一条启用状态的供应商，用户拥有修改权限
- **WHEN** 用户把该供应商的联系人改成新值，并把状态改为停用后提交
- **THEN** 返回成功，再查询该供应商时联系人为新值，状态为停用（1）

#### Scenario: A14 返回该供应商的完整档案信息
- **GIVEN** 系统中有一条供应商，用户拥有修改权限
- **WHEN** 用户打开该供应商的详情
- **THEN** 返回该供应商的完整档案信息

#### Scenario: A30 再查询该供应商时编码仍为 X，系统中没有编码为 Y 的供应商
- **GIVEN** 系统中有一条编码为 X 的供应商，用户拥有修改权限
- **WHEN** 用户提交修改，把该供应商的编码改为另一个值 Y
- **THEN** 再查询该供应商时编码仍为 X，系统中没有编码为 Y 的供应商

#### Scenario: A31 修改失败，并提示名称必填，再查询该供应商时名称仍为原值
- **GIVEN** 系统中有一条供应商，用户拥有修改权限
- **WHEN** 用户提交修改，把该供应商的名称清空
- **THEN** 修改失败，并提示名称必填，再查询该供应商时名称仍为原值

#### Scenario: A15 弹窗关闭，页面提示操作成功，列表中这一行显示新名称
- **GIVEN** 管理员已登录前端，列表中有一条供应商
- **WHEN** 管理员点击该行的修改，改动名称后确认
- **THEN** 弹窗关闭，页面提示操作成功，列表中这一行显示新名称

### Requirement: 删除供应商

_Story S5, from FEAT-20260918-001_

As 有供应商删除权限的业务人员, 删除不再需要的供应商档案, so that 供应商列表只保留有效数据.

The system SHALL 支持删除单条，也支持勾选多条后批量删除
The system SHALL 删除前需要用户二次确认
The system SHALL 任何状态的供应商都可以删除，没有删除限制
The system SHALL 删除采用逻辑删除（del_flag），删除后的供应商不再出现在列表和详情中
The system SHALL 没有删除权限的用户在页面上看不到删除按钮（本期不验收），调用删除接口时被拒绝

#### Scenario: A16 返回成功，之后查询列表时不再出现该供应商
- **GIVEN** 系统中有一条供应商，用户拥有删除权限
- **WHEN** 用户删除该供应商
- **THEN** 返回成功，之后查询列表时不再出现该供应商

#### Scenario: A17 返回成功，之后查询列表时这两条都不再出现
- **GIVEN** 系统中有两条供应商
- **WHEN** 用户一次性删除这两条供应商
- **THEN** 返回成功，之后查询列表时这两条都不再出现

#### Scenario: A32 返回成功，之后查询列表时不再出现该供应商
- **GIVEN** 系统中有一条启用状态的供应商，用户拥有删除权限
- **WHEN** 用户删除该供应商
- **THEN** 返回成功，之后查询列表时不再出现该供应商

#### Scenario: A33 不再返回该供应商的档案信息
- **GIVEN** 系统中有一条已被删除的供应商
- **WHEN** 用户按该供应商的主键请求详情
- **THEN** 不再返回该供应商的档案信息

#### Scenario: A18 页面提示删除成功，该供应商从列表中消失
- **GIVEN** 管理员已登录前端，列表中有一条供应商
- **WHEN** 管理员点击该行的删除，并在确认框中确认
- **THEN** 页面提示删除成功，该供应商从列表中消失

### Requirement: 导出供应商 Excel

_Story S6, from FEAT-20260918-001_

As 有供应商导出权限的业务人员, 把供应商数据导出为 Excel 文件, so that 我可以离线查看、归档，或提供给其他部门使用.

The system SHALL 导出文件是 Excel 格式
The system SHALL 导出列包括供应商编码、名称、联系人、联系电话、状态、备注
The system SHALL 状态在文件中按字典 sys_normal_disable 显示为可读文字（正常/停用），而不是 0/1
The system SHALL 导出符合当前查询条件（名称、状态）的全部数据，不分页
The system SHALL 已删除的供应商不导出
The system SHALL 没有导出权限的用户在页面上看不到导出按钮（本期不验收），调用导出接口时被拒绝

#### Scenario: A19 返回一个非空的 Excel 文件，表头包含供应商编码、名称、联系人、联系电话、状态、备注
- **GIVEN** 系统中至少有一条供应商，用户拥有导出权限
- **WHEN** 用户请求导出供应商
- **THEN** 返回一个非空的 Excel 文件，表头包含供应商编码、名称、联系人、联系电话、状态、备注

#### Scenario: A34 导出文件的数据行数等于按同一条件查询得到的总条数，且每一行的状态都是该状态
- **GIVEN** 系统中符合某一状态条件的供应商数量超过列表默认的一页条数
- **WHEN** 用户以该状态为条件请求导出
- **THEN** 导出文件的数据行数等于按同一条件查询得到的总条数，且每一行的状态都是该状态

#### Scenario: A20 浏览器下载一个 Excel 文件
- **GIVEN** 管理员已登录前端，打开了供应商管理页面
- **WHEN** 管理员点击导出
- **THEN** 浏览器下载一个 Excel 文件

#### Scenario: A21 文件中该供应商各列的值与系统一致，状态显示为正常或停用
- **GIVEN** 已导出一个 Excel 文件，系统中有一条已知的供应商
- **WHEN** 用户用 Excel 打开该文件
- **THEN** 文件中该供应商各列的值与系统一致，状态显示为正常或停用
- _manual acceptance_

### Requirement: 按钮级权限控制

_Story S7, from FEAT-20260918-001_

As 系统管理员, 通过角色分别授予供应商的列表、新增、修改、删除、导出权限, so that 不同岗位的人只能进行各自被授权的操作.

The system SHALL 五项权限相互独立，可以任意组合授予
The system SHALL 缺少某项权限时，直接调用对应接口会被拒绝；页面上不显示对应按钮（本期不验收）
The system SHALL 超级管理员拥有全部权限
The system SHALL 不按部门做数据权限隔离：有列表权限的用户都能看到全部供应商

#### Scenario: A22 每次调用都被拒绝，并提示没有权限，供应商数据没有变化
- **GIVEN** 通过系统的角色和用户接口创建了一个只分配供应商列表权限的角色，以及属于该角色的测试用户，该用户已登录；系统中已有一条供应商
- **WHEN** 该用户分别调用新增、修改、删除、导出接口
- **THEN** 每次调用都被拒绝，并提示没有权限，供应商数据没有变化

#### Scenario: A35 返回成功，结果中包含 admin 新增的那条供应商
- **GIVEN** 管理员 admin 新增了一条供应商；另有一个只拥有供应商列表权限、与 admin 不在同一部门的测试用户已登录
- **WHEN** 该测试用户查询供应商列表
- **THEN** 返回成功，结果中包含 admin 新增的那条供应商

#### Scenario: A24 每项操作都成功
- **GIVEN** 管理员 admin 已登录
- **WHEN** 管理员依次执行查询、新增、修改、删除、导出
- **THEN** 每项操作都成功
