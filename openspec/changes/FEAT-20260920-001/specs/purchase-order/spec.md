## ADDED Requirements

### Requirement: 采购单分页查询

_Story S1, from FEAT-20260920-001_

As 采购员, 按单号、供应商、状态和下单日期范围组合条件分页查询采购单列表, so that 我能快速定位到需要跟进的单据.

The system SHALL 查询条件包括：单号（模糊匹配）、供应商、状态（草稿/已提交）、下单日期起止范围，可任意组合，未填写的条件不参与过滤
The system SHALL 列表至少展示：单号、供应商名称、下单日期、状态、合计金额、创建时间
The system SHALL 结果分页返回，包含总条数；默认按下单日期倒序、同日期按创建时间倒序
The system SHALL 列表页展示的合计金额与该单据明细金额之和一致
The system SHALL 不做数据权限隔离：任何拥有采购单查询权限的用户都能查询到全部采购单，与单据的创建人和部门无关
The system SHALL 前端页面挂在『业务管理』目录下，路径与菜单配置一致

#### Scenario: A1
- **GIVEN** 系统中已存在若干采购单，其中仅有一张单号包含片段『X9』
- **WHEN** 以单号片段『X9』发起分页查询
- **THEN** 返回结果只包含该单号匹配的单据，总条数为 1

#### Scenario: A2
- **GIVEN** 系统中存在下单日期分别在查询范围内和范围外的采购单
- **WHEN** 以下单日期起止范围发起查询
- **THEN** 返回结果只包含下单日期落在该范围内（含起止当天）的单据

#### Scenario: A3
- **GIVEN** 系统中同时存在草稿与已提交状态的采购单
- **WHEN** 以状态=草稿发起查询
- **THEN** 返回结果中全部单据的状态均为草稿

#### Scenario: A4
- **GIVEN** 以 admin 登录并进入采购单管理页面
- **WHEN** 在查询区填写单号并点击查询
- **THEN** 表格只展示匹配的单据，且展示单号、供应商、下单日期、状态、合计金额列


### Requirement: 新增采购单及其明细

_Story S2, from FEAT-20260920-001_

As 采购员, 在一个表单里同时录入采购单主信息和多条物料明细并一次保存, so that 我不必分两步操作就能完整记录一次采购需求.

The system SHALL 主表字段：单号、供应商、下单日期、状态、备注、合计金额；明细字段：物料名称、数量、单价、金额
The system SHALL 单号由系统自动生成，格式为前缀『PO』+ 下单日期（yyyyMMdd）+ 当日流水号，全局唯一；用户不可录入或编辑单号，调用方传入的单号一律被忽略
The system SHALL 供应商只能从供应商档案中选择，且候选项仅包含启用状态的供应商
The system SHALL 明细数量必须是大于 0 的正整数；单价必须大于 0 且最多保留 2 位小数；不满足时保存失败并返回可读的校验提示
The system SHALL 每条明细的金额由系统按『数量×单价』计算，不采用调用方传入的金额
The system SHALL 主表合计金额由系统按所有明细金额之和计算，不采用调用方传入的合计金额
The system SHALL 新增保存的采购单状态固定为草稿
The system SHALL 保存时明细至少一条，供应商、下单日期为必填
The system SHALL 前端表单支持动态增删明细行，并实时显示行金额与合计金额；单号在表单中只读或不展示输入框

#### Scenario: A5
- **GIVEN** 存在一个启用状态的供应商
- **WHEN** 提交一张包含该供应商与两条明细的新增请求
- **THEN** 保存成功，查询详情可看到两条明细，且状态为草稿

#### Scenario: A6
- **GIVEN** 新增请求的明细为『数量 2 单价 10』和『数量 3 单价 5』，并故意传入错误的金额与合计金额
- **WHEN** 保存该采购单
- **THEN** 系统以计算值为准，两条明细金额分别为 20 和 15，主表合计金额为 35

#### Scenario: A7
- **GIVEN** 存在一个停用状态的供应商
- **WHEN** 提交使用该停用供应商的新增请求
- **THEN** 保存失败并返回可读的错误提示，系统中不产生该采购单

#### Scenario: A8
- **GIVEN** 一个不含任何明细的新增请求
- **WHEN** 提交保存
- **THEN** 保存失败并返回明细不能为空的提示

#### Scenario: A9
- **GIVEN** 以 admin 登录并打开采购单新增弹窗
- **WHEN** 选择供应商、填写下单日期并添加两行明细后保存
- **THEN** 弹窗关闭、列表中出现该新单据，状态显示为草稿且合计金额等于两行金额之和

#### Scenario: A10
- **GIVEN** 供应商档案中同时存在启用与停用的供应商
- **WHEN** 在新增弹窗中展开供应商下拉框
- **THEN** 下拉候选中只出现启用状态的供应商

#### Scenario: A32
- **GIVEN** 一个携带了自定义单号且下单日期为指定日期的新增请求
- **WHEN** 提交保存并查询该单据详情
- **THEN** 保存成功，单据单号为系统生成的『PO+下单日期+流水号』格式且不等于请求中传入的值

#### Scenario: A33
- **GIVEN** 三个新增请求，明细分别为数量 0、数量 1.5、单价 0
- **WHEN** 依次提交这三个请求
- **THEN** 三次调用都失败并返回可读的校验提示，系统中不产生对应采购单


### Requirement: 修改草稿采购单

_Story S3, from FEAT-20260920-001_

As 采购员, 修改仍处于草稿状态的采购单主信息和明细, so that 我能在正式提交前纠正录入错误或调整采购内容.

The system SHALL 只有草稿状态的采购单允许修改，已提交的单据修改请求必须被拒绝并返回可读提示
The system SHALL 修改支持同时变更主表字段与明细的新增、删除、修改，保存后以本次提交的明细集合为准
The system SHALL 单号不可修改，修改请求中传入的单号一律被忽略
The system SHALL 明细数量与单价沿用新增时的取值与精度约束（数量为大于 0 的正整数，单价大于 0 且最多 2 位小数）
The system SHALL 若单据的供应商在档案中已被停用，修改保存时必须改选为启用状态的供应商，否则保存失败并返回可读提示
The system SHALL 保存后重新计算各明细金额与主表合计金额
The system SHALL 打开修改表单时回显完整的主表信息与全部明细行

#### Scenario: A11
- **GIVEN** 一张草稿采购单含两条明细
- **WHEN** 提交修改请求：删除一条明细、修改另一条明细的数量、并新增一条明细
- **THEN** 保存成功，详情中明细为修改后的两条，合计金额等于这两条金额之和

#### Scenario: A12
- **GIVEN** 一张已提交状态的采购单
- **WHEN** 提交修改请求
- **THEN** 修改失败并返回已提交不可修改的提示，单据内容保持不变

#### Scenario: A13
- **GIVEN** 一张草稿采购单含多条明细
- **WHEN** 在页面上点击该行的修改按钮
- **THEN** 表单回显该单据的供应商、下单日期、备注及全部明细行

#### Scenario: A14
- **GIVEN** 一张草稿采购单
- **WHEN** 修改某条明细的单价并保存
- **THEN** 列表中该单据的合计金额更新为按新单价重算后的值

#### Scenario: A34
- **GIVEN** 一张草稿采购单，其供应商随后在档案中被停用
- **WHEN** 保持该停用供应商不变提交修改保存请求
- **THEN** 保存失败并返回需改选为启用状态供应商的可读提示，单据内容保持不变


### Requirement: 查看采购单详情

_Story S4, from FEAT-20260920-001_

As 采购员, 查看一张采购单的完整主信息与全部明细, so that 我能在不进入编辑态的情况下核对单据内容.

The system SHALL 详情返回主表全部字段（含单号、供应商名称、状态、合计金额、备注）与明细列表
The system SHALL 已提交与草稿单据都可查看详情
The system SHALL 供应商是否被停用不影响详情查看
The system SHALL 查询不存在的采购单时返回可读的失败信息，不返回空壳数据

#### Scenario: A15

- **WHEN** 按该单据 ID 查询详情
- **THEN** 返回主表字段与三条明细，合计金额等于三条明细金额之和

#### Scenario: A16
- **GIVEN** 一个系统中不存在的采购单 ID
- **WHEN** 按该 ID 查询详情
- **THEN** 接口返回失败且带有可读的错误提示


### Requirement: 删除草稿采购单

_Story S5, from FEAT-20260920-001_

As 采购员, 删除不再需要的草稿采购单, so that 列表中不会残留无效单据干扰查询.

The system SHALL 只有草稿状态的采购单允许删除，已提交的单据删除请求必须被拒绝并返回可读提示
The system SHALL 支持单条删除与勾选多条批量删除
The system SHALL 删除后该单据及其明细都不再出现在列表与详情查询结果中
The system SHALL 删除前需要在页面上进行二次确认

### Requirement: 提交采购单

_Story S6, from FEAT-20260920-001_

As 采购员, 把确认无误的草稿采购单提交, so that 单据内容被冻结，后续环节可以据此开展采购.

The system SHALL 提交将状态由草稿变为已提交
The system SHALL 只有草稿状态的单据可以提交，对已提交单据再次提交必须失败并返回可读提示
The system SHALL 提交时校验明细至少一条
The system SHALL 提交不校验供应商的启用状态：供应商已被停用的草稿单据仍可正常提交
The system SHALL 已提交是终态，不提供撤回、反提交或作废操作；提交成功后该单据不可再修改、不可再删除
The system SHALL 提交使用独立的按钮权限标识，与新增/修改权限分开授权

#### Scenario: A20
- **GIVEN** 一张含明细的草稿采购单
- **WHEN** 调用提交接口
- **THEN** 提交成功，详情中状态变为已提交

#### Scenario: A21
- **GIVEN** 一张已提交的采购单
- **WHEN** 再次调用提交接口
- **THEN** 提交失败并返回状态不允许提交的提示，状态保持为已提交

#### Scenario: A22
- **GIVEN** 一张刚被提交的采购单
- **WHEN** 依次调用修改接口与删除接口
- **THEN** 两次调用都失败并返回可读提示，单据内容与状态均未变化

#### Scenario: A23
- **GIVEN** 页面列表中一张草稿采购单
- **WHEN** 点击该行的提交按钮并确认
- **THEN** 列表中该行状态变为已提交，且该行的修改与删除按钮不可用

#### Scenario: A24
- **GIVEN** 一个未被授予提交权限的登录用户
- **WHEN** 调用采购单提交接口
- **THEN** 接口返回无权限，单据状态保持为草稿

#### Scenario: A35
- **GIVEN** 一张草稿采购单，其供应商随后在档案中被停用
- **WHEN** 查询该单据详情并调用提交接口
- **THEN** 详情正常返回完整主表与明细，提交成功且状态变为已提交


### Requirement: 导出采购单 Excel

_Story S7, from FEAT-20260920-001_

As 采购主管, 把当前查询条件下的采购单导出为 Excel, so that 我能在表格里做线下汇总与留档.

The system SHALL 导出使用与列表查询相同的过滤条件，导出的是全部匹配数据而非仅当前页
The system SHALL 导出内容仅为主表数据，一张采购单占一行，包含单号、供应商名称、下单日期、状态、合计金额、备注等主表字段，不包含明细行
The system SHALL 导出需要导出按钮权限，无权限时接口拒绝
The system SHALL 导出文件为 Excel 格式，列标题为中文业务名称，状态显示为中文而非原始码值

#### Scenario: A25
- **GIVEN** 系统中存在草稿与已提交的采购单
- **WHEN** 以状态=已提交调用导出接口
- **THEN** 接口返回成功且响应为 Excel 文件内容（非空二进制）

#### Scenario: A26
- **GIVEN** 一个未被授予导出权限的登录用户
- **WHEN** 调用导出接口
- **THEN** 接口返回无权限，不产生任何文件内容

#### Scenario: A27
- **GIVEN** 按查询条件导出得到的 Excel 文件
- **WHEN** 用 Excel 打开该文件
- **THEN** 列标题为中文业务名称，状态显示为『草稿』或『已提交』，每张采购单占一行且带合计金额，数据行与页面查询结果一致
- _manual acceptance_


### Requirement: 菜单与按钮级权限控制

_Story S8, from FEAT-20260920-001_

As 系统管理员, 把采购单管理挂在『业务管理』目录下并按按钮粒度授权, so that 不同角色只能看到并执行被授权的操作.

The system SHALL 在『业务管理』目录下新增『采购单管理』菜单，页面路径与菜单配置一致
The system SHALL 按钮级权限至少覆盖：查询、新增、修改、删除、提交、导出，每个后端接口都做对应校验
The system SHALL 未登录调用任何采购单接口返回未登录错误
The system SHALL 已登录但缺少对应权限时接口返回无权限，页面上对应按钮不展示
The system SHALL 权限只控制功能可用性，不限制可见的数据范围：拥有查询权限即可查询全部采购单

#### Scenario: A28
- **GIVEN** 以 admin 登录系统
- **WHEN** 打开左侧菜单
- **THEN** 『业务管理』目录下出现『采购单管理』菜单，点击可进入采购单列表页

#### Scenario: A29
- **GIVEN** 未登录（不携带有效凭证）
- **WHEN** 调用采购单列表接口
- **THEN** 接口返回未登录错误，不返回业务数据

#### Scenario: A30
- **GIVEN** 一个只被授予查询权限的登录用户
- **WHEN** 依次调用新增、修改、删除接口
- **THEN** 三次调用都返回无权限，而列表查询可正常返回数据

#### Scenario: A31
- **GIVEN** 一个只被授予查询权限的用户登录前端
- **WHEN** 打开采购单列表页
- **THEN** 页面可见列表数据，但新增、修改、删除、提交、导出按钮均不展示
